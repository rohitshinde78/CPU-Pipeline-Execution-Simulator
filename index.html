    Performance

    Calculation assumptions
    • Ideal cycles = n + k − 1, where n = instructions that really execute and k = number of stages (no hazards at all).
    • Stall cycles = total cycles − ideal cycles (every extra cycle caused by data, control or structural hazards).
    • Non-pipelined model: one instruction runs completely before the next starts, one cycle per stage, so cycles = n × k.
    • Speedup = non-pipelined cycles ÷ pipelined cycles. Efficiency = speedup ÷ k × 100%.
    • Every stage takes exactly one cycle and the clock time is the same in both models.
    • Wrong-path instructions are flushed and are not counted as completed.
    Rules used by the simulator
    • Register file: writes happen in the first half of WB, reads in the second half of ID, so a value written in WB can be read in that same cycle.
    • Data hazard (RAW): a consumer in ID needs a register that an older instruction in a later stage has not written yet.
    • Forwarding ON: an ALU result can be used right after its last execute stage; a load result right after its MEM stage. If the result is not ready yet (load-use), the pipeline stalls until it is.
    • Forwarding OFF: the consumer waits in ID until the producer reaches WB.
    • Automatic stall OFF: data hazards are only reported and the consumer reads an OLD value (wrong result). Control and structural hazards are still handled, because the hardware cannot skip them.
    • Stall: the consumer stays in ID, earlier stages wait, and a bubble (empty slot) enters the next stage.
    • Branches resolve in the last execute-start stage (EX, or EX2 for 6/7 stages). Stall: fetch stops until the result is known. Predict not taken / taken: fetch follows the guess; a wrong guess flushes the wrong-path instructions and fetch restarts the next cycle. (Predict taken assumes the target address is known at fetch.)
    • Structural hazard: with a single shared memory, when a LW/SW is in MEM, no instruction can be fetched in that cycle.
    • Stage counts: 3 stages merge decode and memory into EX, so no data hazards can occur. 4 stages merge MEM into EX (loads are ready after EX). 6 and 7 stages split EX / MEM / IF, so results take longer and stalls grow.
